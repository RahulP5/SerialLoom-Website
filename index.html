SerialLoom is free, open-source virtual serial port software. Create virtual COM ports and null-modem pairs, share one port between many apps, and bridge serial devices to the network, all in a live visual editor.

Features

Everything you need to work with serial ports

Usually only one program can open a COM port, and two programs cannot talk to each other without a cable. SerialLoom fixes both.

Virtual COM ports

Create COM20, COM21, … that any Windows program can open. Baud rate, timeouts, DTR/RTS and WaitCommEvent behave like a real port.

Null-modem pairs

Two virtual ports wired together, so two programs talk as if connected by a cable. Ideal for testing serial software.

Split

Share one physical port, like a GPS on COM3, with several programs. Each gets its own virtual port.

Join

Merge several serial ports into one virtual port, so one program can read from many devices.

Bridge to TCP/IP

Wire any two endpoints: COM ↔ COM, COM ↔ TCP server, COM ↔ TCP client. Serial over Ethernet, Wi-Fi or VPN.

Bus

Every endpoint hears every other, like an RS-485 multidrop line. Simulate a fieldbus on one PC.

Live visual topology

Drag ports onto the canvas and connect them. Every link shows its throughput as data flows.

Traffic monitor

Inspect the bytes passing through any connection in ASCII or hex, with timestamps and the sending port.

Any baud rate

300 baud to 12 Mbaud, standard or custom, any framing. See the speed each program chose at a glance.
See every byte

A serial port monitor built in

Click any connection to see its endpoints, byte counters and live traffic. Switch between ASCII and hex, pause the stream, and spot which program sent what.

  • Per-port byte counts, throughput and dropped data
  • Baud rate and framing (like 9600 8N1) chosen by each program
  • Add or remove endpoints while data is flowing
  • Connections are saved and start again when SerialLoom opens
How it works

Real COM ports, without an unsigned driver

Most virtual serial port tools need their own kernel driver. SerialLoom presents each port to Windows as a software USB serial device instead, so Windows uses drivers it already trusts.

01 · YOUR PROGRAM

Opens COM20

PuTTY, Arduino IDE, PLC tools, your own code: nothing changes for them.

02 · WINDOWS

usbser.sys

Windows' built-in USB serial driver handles the port like any USB adapter.

03 · SIGNED BY MICROSOFT

Virtual USB controller

The bundled usbip-win2 controller plugs SerialLoom's software device in.

04 · SERIALLOOM

Routes your data

Split, join, pair, bus or bridge to TCP, with live throughput.

Secure Boot stays on. No test-signing mode, no disabling driver signature enforcement. The installer sets everything up, and uninstalling removes the virtual ports it created.

Quick start

Up and running in a minute

  1. Install

    Download the installer and run it. It sets up everything virtual ports need. Windows asks for administrator permission once.

  2. Create or drag

    Press Virtual pair, or drag a real port such as COM3 onto the canvas and choose Split, Join, Bridge or Bus.

  3. Point your apps

    Open the new COM ports in your programs. Watch the data flow on the canvas and in the traffic monitor.

FAQ

Frequently asked questions

Is SerialLoom free?

Yes. SerialLoom is free for personal and commercial use and open source under the MIT license. There is no trial, no feature limit and no account.

Do I need to enable test mode or disable driver signature enforcement?

No. Virtual ports are served by Windows' own USB serial driver (usbser.sys) through a bundled virtual USB controller whose drivers are signed by Microsoft. Secure Boot and driver signature enforcement stay on. How it works.

Which versions of Windows are supported?

Windows 10 version 1803 or later and Windows 11, on 64-bit (x64) PCs.

Will my program see the virtual port as a real COM port?

Yes. To Windows, each virtual port is an ordinary USB serial device, listed in Device Manager under Ports (COM & LPT) as “USB Serial Device (COM20)”. Any program that opens COM ports works with it: terminal programs such as PuTTY or Tera Term, the Arduino IDE, PLC software, navigation apps and your own code using the Win32 API, .NET SerialPort, pySerial and so on.

Can two programs use the same COM port at the same time?

Normally Windows lets only one program open a COM port. SerialLoom's Split gives each program its own virtual port connected to the real one, so a GPS on COM3 can feed three apps at once. Learn how to split a serial port.

How do I create a virtual null-modem cable?

Press Virtual pair in the toolbar. SerialLoom creates two virtual COM ports wired together; whatever one program writes to the first port, the other program reads from the second. Virtual null-modem guide.

Can I access a serial port over the network?

Yes. A Bridge connects a COM port to a TCP server or TCP client, so you can reach a serial device from another PC, or give a remote device a local COM port. Serial to TCP/IP guide.

Which baud rates are supported?

Programs can pick any speed from 300 baud to 12 Mbaud, standard or custom, with any data bits, parity and stop bits. SerialLoom shows each program's choice in the topology. Virtual ports move data at full speed whatever the setting; real ports use the speed you set for them.

Do virtual ports keep their COM numbers?

Yes. You can choose the number (for example COM20) and Windows keeps it for that port on every start. Virtual ports exist while SerialLoom runs, including when its window is closed to the notification area. Saved connections start again automatically when SerialLoom opens.

Why does Windows SmartScreen warn about the installer?

The installer is not code-signed yet, so SmartScreen shows “Windows protected your PC” for new downloads. Choose More info > Run anyway. The installer is built from the public source code by GitHub Actions, and you can read or build it yourself.
