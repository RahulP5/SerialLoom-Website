Share one COM port between several programs

Windows lets only one program open a serial port. SerialLoom's splitter gives every program its own virtual COM port, all connected to the same device.

Download for Windows Read the guide

The problem: “Access denied” on a COM port

When a program opens a serial port, Windows gives it exclusive access. Start a second program on the same port and it fails with Access is denied or port in use. That is a problem when one device needs to feed several programs: a GPS that both a chart plotter and a logger need, or an Arduino you want to watch in the serial monitor while a script records its output.

The fix: split the port

A serial port splitter opens the real port once and shares it through several virtual ports. Each program opens its own virtual port, so none of them get in each other's way.

  1. Install SerialLoom.
  2. In the topology view, drag the real port (for example COM3) from the port list onto the canvas.
  3. Choose Split. Keep the “New virtual port” outputs, add more if you need them, and press Create split.
  4. Point each program at one of the new ports, such as COM20, COM21 and COM22.

How data flows

  • From the device: everything the real port receives is copied to every virtual port.
  • To the device: what any program writes to its virtual port is sent to the real device.
  • Baud rate: the real port runs at the speed you set for it in SerialLoom. Programs on the virtual ports can choose any setting; their data is not slowed down.

Splitting works best when one program does the talking and the others listen. If several programs send commands at the same moment, the device receives them in the order they arrive.

Popular uses

  • GPS and NMEA 0183: share a USB or serial GPS between navigation software, a track logger and AIS or weather apps.
  • Arduino, ESP32 and microcontrollers: keep the serial monitor open while a Python script or data logger reads the same stream.
  • Lab instruments and scales: send readings to your data acquisition software and a backup logger at once.
  • Barcode and RFID readers: feed scans to more than one application.
  • Debugging: eavesdrop on a device's traffic with the built-in traffic monitor while your normal software keeps working.

Join: the opposite direction

Need one program to read from several devices? A Join merges several ports into a single virtual port. Drag the ports onto the canvas, choose Join, and open the joined port in your program.

Questions

Can I add or remove programs later?

Yes. Select the split and use Add endpoint, or remove an endpoint, while data keeps flowing.

Does splitting work with USB-to-serial adapters and Bluetooth serial ports?

Yes. Any COM port Windows lists, built-in, USB (FTDI, CH340, CP210x, Prolific) or Bluetooth SPP, can be the source of a split.

Will the split start automatically?

Connections are saved. Enable Start when SerialLoom opens on the split and it starts every time SerialLoom runs.
