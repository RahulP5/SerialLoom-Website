Getting started with SerialLoom

Everything you need to create virtual COM ports and connect serial ports, programs and networks on Windows.

Install

Download the installer and run it. It installs SerialLoom and the Microsoft-signed virtual USB controller that virtual ports use. Because the installer is not code-signed yet, SmartScreen may ask you to confirm: choose More info > Run anyway. Requirements: Windows 10 version 1803 or later, or Windows 11, x64.

The topology view

SerialLoom opens on the Topology view. The left column lists every COM port Windows knows about: built-in ports, USB adapters, Bluetooth serial links and SerialLoom's virtual ports, with what is using each one. The canvas shows your connections as a graph: ports on the outside, and in the middle the hubs that connect them (split, join, bridge or bus). Every link shows live throughput.

Drag a port onto the canvas to start a split, or onto an existing hub to add it. The toolbar has Split, Join, Bridge, Bus and Virtual pair, and Auto-layout tidies the canvas.

Create a virtual port

Open Virtual ports in the sidebar and press New port. Pick a number such as COM20, or let Windows choose. Windows asks for administrator permission, then the port appears in Device Manager as “USB Serial Device (COM20)”. You can also create virtual ports directly while setting up a hub: choose “New virtual port” as an endpoint. More about virtual COM ports.

Virtual null-modem pair

Press Virtual pair. SerialLoom creates two virtual ports wired together. Open one in each program; what one writes, the other reads. More about null-modem pairs.

Split a port

Drag a real port, for example COM3, onto the canvas, keep the “New virtual port” outputs (add as many as you need) and press Create split. Point each program at one of the new ports. Data from the device reaches every program; data from any program goes to the device. The real port is marked M (master) and runs at the baud rate you set for it. More about splitting.

Join ports

A Join merges several ports into one virtual port, for a program that should receive data from several devices. Choose Join, add the ports to merge, and open the joined virtual port in your program.

Bridge to COM or TCP

A Bridge wires two endpoints: COM ↔ COM, COM ↔ TCP server, or COM ↔ TCP client. To share a device on the network, choose your serial port as side A and TCP server 0.0.0.0:7000 as side B. TCP endpoints have no authentication, so use them on trusted networks only. More about serial to TCP.

Bus

On a Bus, every endpoint hears every other endpoint, like devices on an RS-485 multidrop line. Use it to connect three or more programs, or to simulate a fieldbus with several device simulators on one PC.

Traffic monitor

Click a hub to open the inspector. It lists each endpoint with bytes sent and received, current throughput and dropped data, and shows the traffic monitor below: each chunk of data with its time and source port, in ASCII or hex. Pause the stream to read it, or clear it. From the inspector you can also stop and start the hub, add or remove endpoints, and choose whether it starts when SerialLoom opens.

Baud rates

Programs can open a virtual port at any speed from 300 baud to 12 Mbaud, standard or custom, with any data bits, parity and stop bits. The topology shows the setting each program chose (for example 9600 8N1), which helps spot mismatches. Virtual ports always move data at full speed. Real ports use the speed you configure for them in SerialLoom.

Running in the background

Closing the window keeps SerialLoom running in the notification area, so ports and connections stay open. Click the tray icon to bring the window back. Quit SerialLoom in the icon's menu closes every port. Virtual ports exist while SerialLoom runs and come back with the same numbers the next time it starts; hubs set to start automatically resume too.

Renumber and remove ports

Under Virtual ports, Change number gives a port a new COM number; connections using the port follow it. Deleting a port removes it from Windows completely and frees its number. Both take one administrator prompt. Uninstalling SerialLoom removes all of its virtual ports.

Troubleshooting

My program does not list the virtual port

Make sure SerialLoom is running (check the notification area). In Device Manager, the port should appear under Ports (COM & LPT) as “USB Serial Device (COMn)”, and the controller as “USBip 3.X Emulated Host Controller” under USB controllers. Some programs only scan ports when they start, so restart them after creating a port. Diagnostics on the Virtual ports page shows what SerialLoom sees.

The COM number I want is taken

SerialLoom never takes a number that belongs to real hardware, even when that device is unplugged and only its reservation remains. Pick another number, or remove the old device in Device Manager (View > Show hidden devices) first.

“Access is denied” when opening a port

Another program already has the port open. Use a split to share it.

Remote PCs cannot connect to a TCP server

Check that the server listens on 0.0.0.0 (not 127.0.0.1) and that Windows Firewall allows SerialLoom on that network.

Still stuck?

Open an issue on GitHub with your Windows version, SerialLoom version and what you tried. For how SerialLoom works under the hood, read the architecture notes.
