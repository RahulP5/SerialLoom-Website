Serial to TCP/IP: COM ports over the network

Bridge any serial port to a TCP server or client. Reach a PLC, instrument or GPS from another PC, or give your software a local COM port for a device that lives on the network.

Download for Windows Read the guide

Two directions, one feature

SerialLoom's Bridge wires any two endpoints together. For networking, one side is a COM port and the other side is TCP:

  • COM ↔ TCP server: SerialLoom listens on a port such as 0.0.0.0:7000. Anything that connects gets the serial data, and what it sends goes to the COM port. This shares a local serial device with the network.
  • COM ↔ TCP client: SerialLoom connects out to host:port. Combined with a virtual COM port, this gives a program a local COM port for a remote device, often called a COM port redirector.

The TCP connection carries the raw serial bytes, with no extra protocol, so it works with tools that offer a “raw” TCP mode, with netcat, with your own socket code, and with serial device servers set to raw TCP mode.

Share a serial device on the network

  1. On the PC with the device, open SerialLoom and press Bridge.
  2. Pick the device's port (for example COM4) as side A and set its baud rate.
  3. Pick TCP server as side B, with address 0.0.0.0 and a port such as 7000. Allow SerialLoom through Windows Firewall if asked.
  4. From another machine, connect to pc-name:7000, for example with PuTTY's Raw connection type.

Use a remote device as a local COM port

Your software only speaks COM ports, but the device is on another PC or behind a serial device server? Give it a virtual port:

  1. On your PC, press Bridge.
  2. Side A: a new virtual port, for example COM20.
  3. Side B: TCP client pointing at the remote side, for example 192.168.1.50:7000.
  4. Open COM20 in your program. It talks to the remote device as if it were plugged in locally.

Combine both recipes on two PCs running SerialLoom and you have a full serial-over-Ethernet link between them, across a LAN, Wi-Fi or VPN.

Where this helps

  • Industrial automation: program and monitor PLCs, drives and CNC machines from the office instead of the shop floor.
  • Labs: collect data from instruments in another room or on a shared bench PC.
  • Remote support: reach a customer's device over a VPN.
  • Virtual machines and containers: pass a host's serial device into a VM or test environment over TCP.

Security: SerialLoom's TCP endpoints have no authentication or encryption. Bind them to trusted networks only, or reach them through a VPN or SSH tunnel. Listening on 127.0.0.1 instead of 0.0.0.0 keeps a server local to the PC.

Questions

Does SerialLoom support RFC 2217?

Not yet. The bridge carries raw bytes, which most tools and device servers support. RFC 2217, which also carries baud rate and modem lines over TCP, is on the roadmap.

Can several clients connect to the TCP server?

Use a split or a bus when several parties need the same data; each gets its own endpoint and you can see each one's traffic separately.

Does it work over Wi-Fi or the internet?

It works over any IP network. For anything beyond a trusted LAN, use a VPN, since the TCP connection is not encrypted.
