A virtual null-modem cable for Windows

Create two virtual COM ports wired together, so two programs on the same PC can talk as if a serial cable connected them.

Download for Windows Read the guide

What is a virtual null-modem?

A null-modem cable connects two serial ports directly, crossing the transmit and receive lines so that what one side sends, the other receives. A virtual null-modem (or virtual serial port pair) does the same thing in software: it creates two COM ports, and every byte written to one comes out of the other.

It is the standard way to test serial software without hardware: connect your application to a device simulator, a terminal, or a test script, all on one PC.

Create a virtual serial port pair

  1. Install SerialLoom.
  2. Press Virtual pair in the toolbar of the topology view (or New pair under Virtual ports).
  3. SerialLoom creates two virtual ports, for example COM30 and COM31, and connects them.
  4. Open COM30 in one program and COM31 in the other. Type in one, read in the other.

Typical uses

  • Developing serial software: run your application against a simulator script instead of a real instrument, PLC or modem.
  • Automated tests: drive a COM-port-based program from pySerial, .NET or Node in CI or on your desktop.
  • Connecting two legacy programs: link a program that outputs data on a COM port to one that reads data from a COM port.
  • Simulating devices: replay recorded NMEA, Modbus RTU or barcode scanner data into the software under test.
  • Learning and teaching: experiment with serial protocols with two terminal windows and no wiring.

See what passes between the programs

Click the pair's connection to open the inspector. The traffic monitor shows every chunk of data with a timestamp and the port that sent it, in ASCII or hex. The topology also shows the baud rate and framing each program chose, so you can spot a mismatched setting at a glance.

More than a pair

A pair is a bridge between two virtual ports. The same canvas also lets you build larger setups:

  • Add a third program with a bus, where every port hears every other.
  • Put a real device in the middle with a split, so your app and a logger both see its data.
  • Move one end of the pair to another PC with a TCP bridge.

Good to know: data passes between the two ports at full speed regardless of the baud rate either program sets. Mirroring baud rate and the DTR/RTS lines to the other side is on the roadmap.

Questions

Is this the same as com0com?

It serves the same purpose as com0com's paired ports, but runs on 64-bit Windows 10 and 11 without test-signing mode and adds a visual editor, splitting and TCP bridging. Full comparison.

Can I choose the COM numbers of the pair?

Yes. Pick the numbers when you create the pair, or use Change number later.

Do both programs need to use the same baud rate?

No. Virtual ports do not slow data down to the baud rate, so the programs exchange data even with different settings. The topology shows each program's setting in case the real device will care.
