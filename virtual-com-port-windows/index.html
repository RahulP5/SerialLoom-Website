What is a virtual COM port?

A virtual COM port (also called a virtual serial port) is a serial port that exists only in software. To your programs it looks exactly like a physical RS-232 port or a USB-to-serial adapter: it has a name such as COM20, you can open it, set a baud rate, toggle DTR and RTS and read and write bytes. Behind the scenes, SerialLoom decides where those bytes go: to another program, to a real serial device, or across the network.

Virtual COM ports are useful whenever you need more serial ports than you have, need to connect two programs without a cable, or need to send serial data somewhere a cable cannot reach.

Create a virtual COM port in SerialLoom

  1. Download SerialLoom and run the installer.
  2. Open Virtual ports in the sidebar and press New port, or New pair for two ports wired together.
  3. Choose a port number, for example COM20, or let Windows pick the next free one. Windows asks for administrator permission.
  4. The port appears in Device Manager under Ports (COM & LPT) as “USB Serial Device (COM20)”. Open it from any program.
  5. Connect it on the canvas: split a real port into it, bridge it to TCP, or pair it with another virtual port.

Need a different number later? Use Change number on the port. Connections using the port follow the new name automatically.

How SerialLoom creates COM ports without test mode

Windows only loads kernel drivers that Microsoft has signed. Many virtual serial port drivers are not, so on 64-bit Windows you would have to turn on test-signing mode, which also means turning off Secure Boot.

SerialLoom takes a different route. It presents each virtual port to Windows as a software USB CDC-ACM serial device, plugged into a bundled virtual USB host controller (usbip-win2, whose drivers are signed by Microsoft). Windows then loads its own built-in drivers, usbccgp.sys and usbser.sys, exactly as it does for a USB serial adapter.

Your program ──opens COM20──► usbser.sys            (Windows' built-in USB serial driver)
                                  │
                     Virtual USB host controller   (usbip-win2, signed by Microsoft)
                                  │  loopback only (127.0.0.1)
                     SerialLoom ──► split, join, pair, bus, TCP…

The result: real COM ports that work with Secure Boot on, on any Windows 10 (1803 or later) or Windows 11 PC.

What behaves like a real port

  • Baud rate and framing: programs can choose any speed from 300 baud to 12 Mbaud and any data bits, parity and stop bits. SerialLoom shows each program's choice.
  • Timeouts and events: read and write timeouts and WaitCommEvent work as programs expect.
  • DTR and RTS: programs can set the modem control lines, and SerialLoom sees when a program opens the port.
  • Speed: data between virtual ports is not slowed down to the baud rate; it moves at full speed.

Port numbers that stay put

When you ask for a specific number, SerialLoom claims it in Windows' COM port database, the same way Device Manager's Port Settings > Advanced does. Windows remembers it, so the port comes back with the same number every time SerialLoom starts. SerialLoom never takes a number that belongs to real hardware, even if that device is unplugged at the moment.

Virtual ports exist while SerialLoom is running. Closing the window keeps SerialLoom in the notification area, so the ports stay open; Quit SerialLoom in the tray menu closes them. Deleting a port removes it from Windows completely, and uninstalling SerialLoom removes all of its ports.

Works with your software

Because Windows sees a normal USB serial device, anything that talks to COM ports works: terminal programs such as PuTTY, Tera Term, RealTerm and CoolTerm; the Arduino IDE and PlatformIO; PLC and CNC software; GPS and navigation apps; and your own code using the Win32 serial API, .NET System.IO.Ports.SerialPort, pySerial, Node SerialPort or Rust serialport.

Questions

How many virtual COM ports can I create?

As many as you need for your setup. Each virtual port is a separate USB serial device with its own COM number.

Does a virtual COM port work after a reboot?

Yes, once SerialLoom is running again. Ports come back with the same COM numbers, and saved connections start automatically when SerialLoom opens.

Can I name a virtual port COM1 or COM2?

Yes, if no real hardware owns that number. This helps legacy software that only works with low COM numbers.

Is it really free for commercial use?

Yes. SerialLoom is MIT licensed: free to use at work, in a factory, or in a product, with no license keys.
